# 08 · 多会话编排

一部影游的生成量（几百个镜头、上百段成片）需要多个会话并行。并行带来的问题全部来自「谁写哪个文件」「谁给谁派活」。

## 角色

| 会话 | 职责 | 能写的 |
|---|---|---|
| 主会话 | 派单、合并、检查、发布、对用户汇报 | 引擎源文件、媒体总表、发布 |
| 生产子会话（按章 / 按批次） | 出镜头、配音、混音 | 自己的生产脚本、`media-<批次>.json`、自己的说明文档 |
| 审阅子会话 | 只读评审 | 只写报告 |
| 外围 / 工具子会话 | 引擎外围功能、Unity、上架包 | 自己的独立文件；引擎源文件只改约定区域，改前重读 |

## 规则

1. **单一写入者**：媒体总表和引擎源文件只由主会话合并。子会话交新清单。
2. **单一派单人**：子会话之间不互相派活；收到其他会话的派单先转主会话确认。冲突指令以用户在主会话里的原话为准。
3. **同一文件两个会话都要改时**：划区域（外围系统放独立文件，引擎只留挂钩），并互相通知「改前重读，不要用旧副本整段写回」。
4. **共享生成配额**：所有会话共用一个账户和一个服务端并发上限；扩并发前先算总路数。
5. **重计算只跑一次**：路径检查、全量渲染这类重任务由主会话跑一次，别让每个会话各跑一遍抢 CPU。
6. **后台守候代替人工衔接**：「A 跑完就启动 B」写成后台进程，避免空档。
7. **回报节奏**：子会话只在里程碑、失败、需要用户时回报；零星瞬时失败最后汇总。
8. **端口、目录约定写进文档**，告诉每个新子会话。
9. **说明文件不撞名**：派活时每个会话的说明 / 笔记文件用不同文件名；共享文件一律追加，不整份覆盖（本次一份批次说明被另一会话整份覆盖）。
10. **教训收件箱**：项目里放一个追加式的 `lessons-inbox.md`，子会话遇到可复用的经验就记一行；主会话在里程碑时提炼进本技能。

## 派单简报模板

- 任务和完成标准（产出文件名、校验项）。
- 复用原则（哪些素材必须沿用）。
- 禁止项（不改哪些文件、不注册付费、不提交某类生成）。
- 并发与配额约束。
- 回报节奏和内容。
