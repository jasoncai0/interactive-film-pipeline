# 07 · 打包与上架

## Unity：验证一次，最终版再打

- **路线**（三选一后推荐）：Unity 内嵌纯 C# 的 JS 解释器（Jint）直接跑 Web Demo 的数据段，C# 只做播放和界面。剧本改动重新导出一次即同步，不维护两份剧情。
  - 风险：「剧情怎么往下走」的流转规则在 Web 引擎和 Unity 各有一份，Web 改了规则 Unity 要手动同步；更新的 JS 语法 Jint 不一定支持；IL2CPP 要防裁剪。
- 首包只求跑通：导出 → 流程测试（固定路线 + 随机走局）→ 打 macOS 包 → 自动驾驶截图。
- 验证可行后**冻结**，写清「最终版打包步骤」（编辑器版本、许可、依赖、三条命令），中间调试一律用 Web 版。
- 最终版前的工程待办：存档改写文件（云存档前提）、成就移植、Windows 包（另装平台模块）、Mac 签名公证脚本、正式 UI、视频管线（双播放器预加载、VP8 备份给 Steam Deck）。

## Steam：上架前置包

### 必须用户本人做（按顺序）

1. 注册 Steamworks 合作伙伴（先定个人还是公司主体），签保密协议和分销协议。
2. 手持证件身份验证。
3. 税务问卷（个人 W-8BEN / 公司 W-8BEN-E）、银行信息（户名与主体一致）。
4. 付 Steam Direct 费用（每款 100 美元），拿到 App ID。
5. Mac 包：Apple Developer（99 美元 / 年）签名并公证。
6. 构建上传账号与凭证、内容问卷（一般内容、成人内容、AI 披露）提交、定价、发售日、「送审 → 即将推出 → 发布」。
7. 国区策略（版号）先问律师。

### 会话可以全部备好的

- 上架流程文档（附官方链接与查阅日期）。
- 中英商店文案：短描述（≤300 字符）、长描述（BBCode）、20 个标签（对照官方标签表）、系统需求、不剧透真结局。
- 全套胶囊图与库资产（按官方现行尺寸逐一校验），截图取自高清母版原帧，图标全套。
- 预告片：主预告 60–90 秒 1080p；另剪 30 秒**全年龄版**（无流血 / 处决 / 火烧），标好上传顺序。避开有违规风险的镜头（如主角露嘴）。
- AI 披露草稿：哪些内容 AI 生成（图、视频、配音、音乐）、用了哪些工具、人工做了什么；剧本是否 AI 参与由用户裁定。保留付费凭证和生成平台当时的用户协议存档，证明商用授权。
- 成就表（API 名、中英名称描述、64 / 256 图标、剧透成就标隐藏）、SteamPipe 构建模板（App ID 用占位符）、云存档方案、引擎接入方案。
- 一个校验脚本，产出尺寸 / 时长 / 编码的合格报告。

### 时间线（最短）

Day 0 付费并提交商店页（等待期开始）→ Day 1–2 上传构建送审 → Day 4–8 商店页通过、点「即将推出」，至少预热 14 天 → 最早约 Day 22 发售。实际按 5 周排；被打回一次多 3–5 个工作日。

### 风险

- AI 披露是送审必填项；剧情和本地化也在披露范围内。
- 国区：没有版号的游戏在国区销售属于灰色地带，可能被要求锁区或下架。
- Steam Deck：H.264 在 Proton 下不可靠，备 VP8。
