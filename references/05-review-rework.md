# 05 · 评审与返工

## 评审由独立子会话做

- 审阅会话只读：只写报告，不改源文件、不改媒体、不派活。它给出的修法由主会话评估后执行。
- 每轮报告固定结构：结论与分项评分 → 上轮问题核销表 → P0 / P1 / P2（每条：场景 · 证据（成片时间点或代码行）· 修法 · 是否需要补镜）→ 专项（音画对照、口播规范、爽点曲线、旗标闭环、梗）→ 做得好的地方 → 验证方法。
- 让审阅会话用**随机走局**（3–6 万局）统计结局分布和条件闭环，而不是只读代码。
- 本次四轮：7/7/8/8 → 终审 8/10，P0 从有到清零。

## 评审维度

1. 逻辑自洽与史实走向。
2. 爽点和剧情推进的排布（曲线，见 01）。
3. 抓人点（开场钩子、每章钩子）。
4. 梗的位置与化用。
5. 终审加：成片字幕 × 剧本逐条对照、口播规范（旁白句数、主角不露嘴抽帧）、旗标闭环。

## 修法分级（每条问题必须标）

| 级别 | 做法 | 成本 |
|---|---|---|
| 0 | 改文本、条件、引擎字段（`after`、`extra`、`need`、无片过渡场） | 分钟级 |
| 1 | 重配音轨 / 重剪（TTS 重配、旁白删减、心声替换、静帧拼尾） | 不调用视频生成 |
| 2 | 补镜头 | 生成排队 + 积分 |

能用 0 级解决的不用 1 级，能用 1 级的不补镜。补镜清单按批次拆给子会话（见 08）。

## 本次返工目录（以后开工前对照）

| 返工 | 根因 | 以后怎么做 |
|---|---|---|
| 旁白过量，事后重混 40 段 | 口播配比规则定得晚 | 第一镜就按 02 的配比写 |
| 3 段结局片主角露嘴，上架前才发现 | 只在对白镜查嘴，没查静态特写 | 每段成片验收都抽帧查主角的脸 |
| 叠字补句没有声音 | 为了零补拍只加了文字 | 旁白 / 心声类补句随后用 TTS + 末帧静帧拼尾或做插入片 |
| 结局片与结局卡说两遍 | 结局卡沿用了完整文本 | 结局加 `after` |
| 勋贵线结尾同一句连播两次 | 过场片和结局片各念一遍 | 结局片可以删，前一场收尾已足够 |
| 变体台词首周目看不到 | 写在 `lines` 里，有片时不显示 | 变体放 `extra` 或做 `:alt` 片 |
| 条件写反 | 旗标命名有歧义 | 旗标语义写进文档，随机走局验证 |
| 剧本与成片台词漂移 | 子会话按自己的稿子配音 | cues 为真源，合并时回写 |
| 发布漏传资源 | 差量只按媒体清单算 | 差量包含新资源目录 |
| 子会话收到互相冲突的指令 | 子会话之间互相派活 | 只由主会话派单（08） |
| 本地测试清掉了别的项目存档 | 端口撞车 | 固定端口 |

## 补拍 / 重配清单格式

按批次（如 R0 / R2 / R4 / R5-A/B/C、FIX-1/2）列：场景、镜头、改什么、级别、交给哪个会话、产出清单名。每批交付一个 `media-<批次>.json` + 说明文档。
